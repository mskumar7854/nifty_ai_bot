# Phase 3 Architecture Invariants

This document establishes the unbreakable rules for the Replay & Learning Event Model (Phase 3). 
As the system evolves, these invariants must be strictly preserved to guarantee the cryptographic auditability and deterministic replay capabilities of the Nifty AI platform.

## 1. ExecutedTrade (The Reality Ledger)
- **Immutable:** Once instantiated, an `ExecutedTrade` can never be modified.
- **Pure Data:** Contains strictly execution facts (what happened) and the `decision_snapshot_id`. It must never contain business logic, AI confidence scores, or predictive analytics.
- **Write Authority:** Only written by the core execution modules at the exact moment a broker fill (or simulated fill) is confirmed.
- **Persistence:** Appended to `immutable_executions.jsonl`. Never updated. Never deleted.

## 2. ExecutionAttribution (The Analytics Ledger)
- **Immutable Post-Creation:** Once generated by the Replay Engine, it is immutable.
- **Read-Only Upstream:** Must never modify the `ExecutedTrade` or `DecisionSnapshot`.
- **Cryptographic Linkage:** Must always contain the `executed_trade_fingerprint` to immutably prove which execution reality it references.
- **Write Authority:** Only written by the Replay Engine.

## 3. LearningEvent (The Adaptation Ledger)
- **Append-Only:** Learning events are purely additive.
- **Non-Destructive:** Must never modify historical attribution data or execution history.
- **Traceability:** Must link back to the exact execution fingerprint and trade ID that triggered the learning.
- **Write Authority:** Only written by the Learning Engine.

## 4. ExecutionLedgerWriter (The Persistence Layer)
- **Append-Only:** Files (`immutable_executions.jsonl`, `execution_attribution.jsonl`, `learning_events.jsonl`) are strictly append-only.
- **No Updates:** The writer must never support `update`, `upsert`, or `delete` operations.
- **Format:** Canonical JSON Lines (`jsonl`).

## 5. ExecutionFingerprint (The Cryptographic Identity)
- **Separation of Concerns:** Fingerprint generation must remain an isolated infrastructure service (e.g., `ExecutionFingerprint.create()`), keeping data models pure.
- **Determinism:** Must use canonical numeric formatting (string rounding) and sorted JSON to prevent floating-point or cross-platform representation drift.

*Rule of Thumb: When evidence conflicts with assumptions, trust the evidence. Everything downstream relies on the immutable execution record.*
